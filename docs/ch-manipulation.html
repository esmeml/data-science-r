3.1 Les données de ce chapitre

3.1.1 La boutique en ligne (données simulées)

Ces données simulent l’activité d’un site de vente en ligne français en 2025. Elles se composent de quatre tables, au format CSV, reliées par des clés : client_id relie les commandes et la campagne aux clients, categorie relie les commandes à la table des catégories.

boutique_clients.csv — 2 000 lignes, une par client inscrit sur le site.

Variable Type Description
client_id texte identifiant du client (C0001 à C2000)
age numérique âge en années ; non renseigné (NA) pour 60 clients
region texte région de résidence (7 régions et « Autres régions »)
canal_acquisition texte canal par lequel le client est arrivé : Direct, Email, Moteur de recherche, Réseaux sociaux, Affiliation (sites partenaires rémunérés à la vente)
date_inscription date date de création du compte (2021 à 2025)
newsletter texte abonnement à la newsletter : Oui / Non

boutique_commandes.csv — 9 508 lignes, une par commande passée en 2025. Certains clients (259) n’ont passé aucune commande en 2025.

Variable Type Description
commande_id texte identifiant de la commande (K00001…)
client_id texte client qui a passé la commande (clé vers clients)
date date date de la commande (du 01/01/2025 au 31/12/2025)
categorie texte catégorie de produits : Mode, Maison, Beauté, High-tech, Sport
nb_articles entier nombre d’articles dans la commande
promo logique TRUE si un code promo (20 % de remise) a été utilisé
montant numérique montant payé, en euros TTC, après remise éventuelle

boutique_categories.csv — 6 lignes, table de référence des catégories.

Variable Type Description
categorie texte nom de la catégorie (clé) ; Jardin n’a aucune commande
taux_marge numérique marge brute, en proportion du montant hors taxes
univers texte regroupement de catégories (Personne, Habitat, Technologie, Loisirs)

boutique_campagne.csv — 944 lignes, une par abonné à la newsletter ayant reçu l’emailing de novembre 2025 (test A/B).

Variable Type Description
client_id texte client destinataire (clé vers clients)
version texte version reçue, tirée au hasard : A (objet habituel) ou B (objet personnalisé avec le prénom)
ouvert logique l’email a été ouvert
clic logique le client a cliqué sur un lien de l’email (implique ouvert)
achat logique le client a acheté après avoir cliqué (implique clic)

Comment les données ont été simulées. Chaque client appartient à l’un de quatre segments « cachés » (non fournis dans les fichiers) : clients fidèles, chasseurs de promotions, clients occasionnels et nouveaux clients. Le segment détermine l’âge, le canal d’acquisition, l’abonnement à la newsletter, le nombre de commandes (loi de Poisson), leur montant (loi log-normale), le recours aux promotions et les catégories achetées. Les dates de commande suivent une saisonnalité, avec un pic en novembre et décembre. Retrouver ces segments est l’objet du chapitre 6.

3.2 Importer et exporter des données

3.2.1 Le répertoire de travail

R lit et écrit les fichiers relativement au répertoire de travail (getwd() pour l’afficher). Avec un projet RStudio, c’est le dossier du projet ; on utilise alors des chemins relatifs.

3.2.2 Lire un fichier CSV

Le format CSV (comma-separated values) est le format d’échange le plus courant. Le package readr fournit read_csv(), qui renvoie un tibble et indique le type deviné pour chaque colonne :

clients   <- read_csv("../datasets/boutique_clients.csv")
commandes <- read_csv("../datasets/boutique_commandes.csv")
campagne  <- read_csv("../datasets/boutique_campagne.csv")
categories <- read_csv("../datasets/boutique_categories.csv")

read_csv() a reconnu automatiquement les dates (date, date_inscription) et les booléens (promo). Vérifiez toujours ces types : un montant lu comme du texte, par exemple à cause d’une virgule décimale, empêche tout calcul.

3.4 Analyse univariée

Les indicateurs et graphiques dépendent du type de la variable : quantitative (un nombre pouvant prendre de nombreuses valeurs : âge, montant) ou qualitative (un nombre limité de modalités : canal, région).

3.4.1 Variable quantitative

Indicateurs de position (centralité)

range(commandes$montant)
#> [1]   6.99 435.71
mean(commandes$montant)
#> [1] 64.55
median(commandes$montant)
#> [1] 54.43

Le montant moyen d’une commande (64.55 €) est nettement supérieur au montant médian (54.43 €) : quelques grosses commandes « tirent » la moyenne vers le haut. La médiane est plus robuste aux valeurs extrêmes. C’est fréquent pour les montants, les revenus ou le nombre de visites : regardez toujours les deux.

Indicateurs de dispersion

sd(commandes$montant)                            # écart-type
#> [1] 41.63
quantile(commandes$montant, c(0.25, 0.5, 0.75))  # quartiles
#>   25%   50%   75% 
#> 34.02 54.43 83.84
quantile(commandes$montant, seq(0.1, 0.9, 0.1))  # déciles
#>    10%    20%    30%    40%    50%    60%    70%    80%    90% 
#>  23.16  30.35  37.84  45.69  54.43  64.40  76.40  93.39 119.44
IQR(commandes$montant)                           # écart interquartile
#> [1] 49.82
summary(commandes$montant)
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
#>    6.99   34.02   54.43   64.55   83.84  435.71

Les déciles sont très utilisés en marketing : « les 10 % de commandes les plus élevées dépassent 119 € ».

Représentation graphique

     main = "Distribution du montant des commandes",

La distribution est asymétrique à droite : beaucoup de petites et moyennes commandes, peu de très grosses.

3.5.1 Deux variables qualitatives : un test A/B

En novembre 2025, la boutique a envoyé une campagne d’emailing à ses abonnés. Chaque abonné a reçu, au hasard, la version A (objet habituel) ou la version B (objet personnalisé avec le prénom). C’est un test A/B : comme l’attribution est aléatoire, une différence de comportement entre les deux groupes peut être attribuée à la version de l’email.

tab_ouv <- table(campagne$version, campagne$ouvert)
tab_ouv
#>    
#>     FALSE TRUE
#>   A   370   95
#>   B   347  132
lprop(tab_ouv)      # pourcentages en ligne (questionr)
#>      
#>       FALSE TRUE  Total
#>   A    79.6  20.4 100.0
#>   B    72.4  27.6 100.0
#>   All  76.0  24.0 100.0

Pourcentages ligne ou colonne ? On calcule les pourcentages dans les modalités de la variable explicative (indépendante). Ici, la version de l’email explique l’ouverture, et elle est en ligne : on lit donc les pourcentages en ligne pour comparer les taux d’ouverture de A et B.

Le taux d’ouverture est plus élevé pour B. Cette différence pourrait-elle être due au hasard du tirage ? Le test du \(\chi^2\) d’indépendance répond à cette question. Son hypothèse nulle est que les deux variables sont indépendantes (ici : que la version n’a aucun effet sur l’ouverture).

chisq.test(tab_ouv)
#> 
#>  Pearson's Chi-squared test with Yates' continuity correction
#> 
#> data:  tab_ouv

3.5.2 Une variable quantitative et une qualitative

Le montant d’une commande dépend-il de l’utilisation d’un code promo ?

boxplot(montant ~ promo, data = commandes,
        names = c("Sans promo", "Avec promo"), ylab = "Montant (€)")

tapply(commandes$montant, commandes$promo, mean)
#> FALSE  TRUE 
#> 79.19 42.86
tapply(commandes$montant, commandes$promo, median)
#> FALSE  TRUE 
#> 70.31 35.88

La formule montant ~ promo se lit « montant en fonction de promo ». Les commandes avec promotion sont nettement plus faibles. Le test t de Student compare les moyennes de deux groupes ; le test de Wilcoxon (non paramétrique) compare leurs distributions sans hypothèse de normalité :

t.test(montant ~ promo, data = commandes)
#> 
#>  Welch Two Sample t-test
#> 
#> data:  montant by promo
#> t = 50, df = 9432, p-value <2e-16
#> alternative hypothesis: true difference in means between group FALSE and group TRUE is not equal to 0
#> 95 percent confidence interval:
#>  34.92 37.74
#> sample estimates:
#> mean in group FALSE  mean in group TRUE 
#>               79.19               42.86
wilcox.test(montant ~ promo, data = commandes)
#> 
#>  Wilcoxon rank sum test with continuity correction
#> 
#> data:  montant by promo
#> W = 1.7e+07, p-value <2e-16
#> alternative hypothesis: true location shift is not equal to 0

Interpréter avec prudence. La remise est de 20 %, mais les commandes en promotion sont plus faibles de près de moitié. Une grande partie de l’écart vient de qui utilise les promotions : les clients « chasseurs de promos » ont de toute façon de petits paniers. C’est un facteur de confusion : conclure que « les promotions divisent le panier par deux » serait faux.

De plus, les tests supposent des observations indépendantes ; or plusieurs commandes viennent du même client. Une analyse rigoureuse raisonnerait au niveau des clients (voir la section dplyr ci-dessous).

Enfin, le test t suppose la normalité des données dans chaque groupe ; avec de grands effectifs (plusieurs centaines par groupe), il reste fiable même si elle n’est pas vérifiée. Le test de normalité de Shapiro-Wilk (shapiro.test()) rejette presque toujours la normalité sur de grands échantillons : un histogramme est plus informatif.

left_join(x, y) toutes celles de x (la plus utilisée)

3.9.2 Tirages aléatoires

Pour chaque loi de probabilité, R fournit quatre fonctions, dont le nom commence par :

Préfixe Rôle Exemple (loi normale)
r tirage aléatoire rnorm(10, mean = 0, sd = 1)
d densité (ou probabilité ponctuelle) dnorm(0)
p fonction de répartition \(P(X \le q)\) pnorm(1.96)
q quantile (inverse de p) qnorm(0.975)

Lois courantes : norm, unif, binom, pois, exp, lnorm, t, chisq, f.

set.seed(42)                         # rend les tirages reproductibles
rbinom(5, size = 1000, prob = 0.03)  # acheteurs parmi 1 000 visiteurs, conversion de 3 %
#> [1] 38 30 36 27 46
rpois(5, lambda = 4)                 # nombre de commandes par client
#> [1] 9 7 1 4 3
rlnorm(3, meanlog = log(50), sdlog = 0.5)   # montants (loi log-normale, asymétrique)
#> [1] 96.50 81.54 77.70
sample(c("A", "B"), 10, replace = TRUE)     # attribution aléatoire d'un test A/B
#>  [1] "B" "A" "B" "A" "B" "B" "B" "A" "A" "B"

Simuler des données permet de tester une méthode sur des données dont on connaît la vérité.Par exemple, on a utilisé ces fonctions pour créer la boutique en ligne : - nombre de commandes selon une loi de Poisson, - montants selon une loi log-normale, - ouvertures d’emails selon une loi de Bernoulli. On a simulé aussi des segments de clients « cachés » que l’on cherchera à retrouver au chapitre 6.

set.seed(1)
detecte <- replicate(1000, {
  achats_a <- rbinom(1, 500, 0.015)
  achats_b <- rbinom(1, 500, 0.025)
  prop.test(c(achats_a, achats_b), c(500, 500))$p.value < 0.05
})
mean(detecte)
#> [1] 0.14

Le test ne détecte la différence que dans une minorité des cas : c’est ce qu’on appelle un manque de puissance, et cela explique le résultat non significatif sur les achats de la campagne.

Exercice 3.8 — Test A/B. À partir de la table campagne :

#>

L’objet personnalisé (B) augmente significativement le taux d’ouverture. L’effet sur les achats va dans le même sens mais n’est pas démontré avec cet échantillon ; on peut généraliser l’objet personnalisé et continuer à mesurer l’effet sur les ventes sur plusieurs campagnes.
